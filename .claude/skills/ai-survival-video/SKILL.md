# AI 생존기 영상 제작

저장소에 남은 **실제 기록**으로 "비개발자가 AI와 함께 살아남아 무언가를 만들어 낸 과정"을 초보자가 따라 할 수 있는 시리즈 영상으로 만든다.
결과물은 모두 `video/` 폴더 안에만 만든다. 대상 프로젝트의 소스코드는 읽기만 하고 절대 수정하지 않는다. 시청자에게 보여줄 기록이 오염되면 안 되기 때문이다.

## 채널 톤 — "AI 생존기"란

- 화자: AI 시대에 커리어를 전환 중인 강사. 개발자가 아니고, Claude Code로 실제 결과물을 만든다.
- 편마다 서사 곡선을 한 번 갖는다: **목표 → AI에게 시킨 것(실제 프롬프트) → 막힘 → 사람이 판단한 지점 → 해결 → 배운 것**
- 콘텐츠의 핵심은 **"AI가 자동으로 한 일과 사람 손이 필요했던 일의 경계"**다. 편마다 이 경계를 최소 한 번 명시적으로 보여준다(explain 장면 권장).
- 과장하지 않는다. "10분 만에 앱 완성" 같은 문구는 기록이 뒷받침할 때만 쓴다.

## 공통 규칙

- 기록(커밋, 문서, 설정)에 없는 내용은 지어내지 않는다. 추정이 필요하면 `[확인 필요]`로 표시하고 목록으로 모은다. 시청자는 이 영상을 따라 하므로, 틀린 명령어 하나가 곧 시청자의 막힘이 된다.
- 화면·자막·내레이션에 나가는 API 키, 토큰, `.env` 값, 비밀번호, 개인 이메일은 `****`로 가린다. `scripts/mask.py`가 렌더링 시 자동으로 가리지만, 대본을 쓸 때부터 직접 가린다(자동 패턴이 모든 형식을 알지는 못한다).
- 무료 도구만 쓴다: edge-tts, Pillow, ffmpeg.
  - 설치: `pip install edge-tts pillow`
  - ffmpeg가 없으면 멈추고 안내한다: Windows `winget install Gyan.FFmpeg`, Mac `brew install ffmpeg`
- 오류가 나면 원인을 고쳐서 최대 3번 재시도한다. 그래도 안 되면 멈추고 보고한다.
- STEP이 끝날 때마다 `video/progress.md`에 `STEP N 완료 + 결과 요약`을 한 단락씩 추가한다. 세션이 끊겨도 이어서 할 수 있게 하려는 것이다.

이 스킬의 스크립트 경로를 `$S`라고 부른다 (`.claude/skills/ai-survival-video/scripts`, 또는 설치된 스킬 폴더의 `scripts`).

## STEP 1 — 작업 기록 수집 (읽기만)

1. 원자료를 한 파일로 모은다:
   ```bash
   python $S/collect_history.py <프로젝트경로> video/research_raw.md
   ```
   - 커밋 타임라인, 모든 `.md`, 스택·배포 설정, 이미지 후보가 비밀정보가 가려진 채 담긴다.
   - 출력에 `shallow: true`가 나오면 `git fetch --unshallow` 후 다시 실행한다.
2. `research_raw.md`를 읽고 `video/research.md`를 쓴다:
   - **시간순 작업 흐름**: 날짜 | 한 일 | 근거(커밋 해시·문서명)
   - **실제 사용한 프롬프트·명령어**: 문서나 커밋 메시지에 남은 것만 인용한다. 원문이 없으면 `[확인 필요]`로 표시한다.
   - **막혔던 문제와 해결법**: fix 커밋, 되돌린 커밋, 문서의 트러블슈팅 항목에서 찾는다.
   - **AI 자동 vs 사람 손**: 기록상 사람이 판단·수정한 흔적(수동 커밋, 방향을 바꾼 문서 등)
   - 기술 스택, 배포·등록 과정 (예: 앱인토스, Vercel)
   - `[확인 필요]` 목록

## STEP 2 — 시리즈 기획 → `video/series_plan.md`

- 4~6편으로 구성한다. 편마다 적을 것:
  - 제목
  - 목표
  - 시청자가 따라 해서 갖게 되는 결과물
  - 예상 길이 (5~8분 ≈ 내레이션 45~70문장)
  - 등장할 실제 프롬프트·명령어
  - 초보자가 막힐 지점과 해결법
  - 이 편의 "AI 자동 / 사람 손" 경계 포인트
- 편 순서는 **커밋 시간순**을 따른다. 시청자가 같은 순서로 재현할 수 있어야 하기 때문이다.
- 마지막에 `[확인 필요]` 목록을 붙인다.

## STEP 3 — 편별 대본 → `video/epNN/script.json`

형식은 `references/script_schema.md`를 읽고 따른다. 핵심 규칙:

- **장면 타입**:
  - `title`: 제목 카드
  - `explain`: 설명
  - `prompt`: 따라 칠 프롬프트를 큰 글씨로
  - `code`: 실제 코드 일부 확대 + 하이라이트
  - `screen`: 캡처 이미지
  - `recap`: 정리 + 다음 편 예고
- **내레이션**:
  - 쉬운 존댓말, 한 문장 40자 이내. 자막이 두 줄 안에 들어오고, 초보자가 한 호흡에 알아듣는 길이다.
  - 전문용어는 처음 나올 때 한 줄로 풀어 준다. 예: "커밋은, 작업을 저장하는 체크포인트예요."
- **도입 15초 안에** "이 편이 끝나면 무엇을 갖게 되는지"를 보여준다 (title 다음 장면).
- `prompt` 장면은 `min_sec` 3 이상으로 둔다. 시청자가 멈추고 따라 칠 시간이 필요하다.
- `code` 장면은 실제 파일에서 15줄 이하만 발췌하고, `start_line`은 원본 줄 번호와 맞춘다.
- `screen` 장면은 STEP 1의 이미지 후보에서 고른다.
  - 없으면 `image`를 비워 둔다. 렌더러가 설명 슬라이드로 대체하고 `need_capture.md`에 캡처 목록을 적는다.
  - `capture_hint`에 무엇을 찍어야 하는지 적는다.
- 마지막 장면은 `recap` + `next`(다음 편 예고)로 끝낸다.
- 챕터로 쓸 장면에는 `chapter`를 넣는다 (upload.txt 타임스탬프가 된다).

## STEP 4 — 렌더링

```bash
python $S/render.py video/epNN/script.json            # edge-tts 음성 (기본)
python $S/render.py video/epNN/script.json --tts none # 음성 없이 타이밍만 (edge-tts가 막힌 환경)
```

렌더러가 하는 일:
- ko-KR-InJoonNeural로 문장별 음성을 만들고 문장 사이에 0.3초 쉼을 둔다.
- 1920×1080 슬라이드를 만든다: 남색 배경, 금색 강조, 좌상단 EP 배지.
- SRT 자막을 한 줄 25자 이내로 만든다.
- 장면마다 약한 줌인을 넣고, 자막을 번인하고, 음량을 -14 LUFS로 맞춘다.
- 산출물 (`video/epNN/`):
  - `epNN.mp4`, `epNN.srt`
  - `thumbnail.png` (1280×720)
  - `upload.txt` (제목·설명·챕터·태그)
  - `need_capture.md` (필요할 때만)
  - `render_report.json`

폰트는 Windows 맑은고딕 → Mac Apple SD 고딕 → Linux Noto CJK 순으로 자동 선택한다.

**클라우드(Claude Code on the web)에서 알려진 제약**: 프록시가 WebSocket을 막아서 edge-tts가 실패한다.
- 이때는 `--tts none`으로 화면·타이밍만 검증한다.
- 실제 음성 렌더링은 사용자 PC에서 하도록 안내한다.
- 음성 없는 영상을 완성본처럼 보고하지 않는다.

## STEP 5 — 자동 점검 + 수정

```bash
python $S/qa.py video/epNN/script.json
```

1. `qa_frames/`의 프레임(10초 간격)을 **이미지로 직접 열어** 확인한다:
   - 글자 잘림
   - 겹침 (특히 하단 자막과 슬라이드 내용)
   - 오타
   - 가려지지 않은 비밀정보
2. `auto_issues`(40자 초과 문장, 25자 초과 자막 줄, 비밀정보 후보, 렌더 경고)를 확인한다.
3. 내레이션과 화면이 안 맞는 구간을 찾는다. 예: 코드 얘기를 하는데 화면은 제목 카드인 경우.
4. 문제가 있으면 `script.json`을 고친다. 반복되는 레이아웃 문제면 `render.py`를 고친다. 그 뒤 다시 렌더링한다 (최대 2회).
5. `video/epNN/qa.md`에 점검 항목, 발견한 문제, 수정 내용, 남은 문제를 기록한다.

## STEP 6 — 보고 후 멈춤

아래를 보고하고 멈춘다. 사용자가 결과를 보고 방향을 정해야 다음 편의 품질이 올라가기 때문이다.
- 시리즈 구성 (편 제목 목록)
- 이번 편 결과: 영상 길이, 장면 수, 파일 위치, TTS 모드
- `[확인 필요]` 항목과 `need_capture.md` 내용
- 수정한 문제 목록

사용자가 **"다음 편 진행"**이라고 하면 다음 편 번호로 STEP 3~5를 같은 방식으로 반복한다.
- research와 series_plan은 다시 만들지 않는다.
- 사용자가 캡처나 `[확인 필요]` 답을 줬다면 먼저 research.md에 반영한다.
