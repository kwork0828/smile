# 채널 벤치마킹 → 대본 → 이미지·영상 프롬프트

원본: AI:ON 「클로드 코드 유튜브 영상 제작 프롬프트」. 흐름은 그대로 두고, 검토에서 나온 보완점을 반영했다 (아래 "원본 대비 바뀐 점").

## 핵심 규칙

- 단계 순서대로 진행하고, **한 단계가 끝나면 멈추고 사용자 답을 기다린다.** 사용자가 고른 주제와 실제 원고가 다음 단계의 재료라서, 앞서 나가면 추측으로 채우게 된다.
- 대본이 확정되기 전에는 이미지·영상 프롬프트를 만들지 않는다.
- **문체는 따라가되 문장은 새로 쓴다.** 원고의 문장을 그대로 옮기는 건 저작권 문제이자 채널 신뢰 문제다. 3단계 끝에 `scripts/text_check.py overlap`으로 연속 6어절 이상 겹치는 구간이 0개인지 확인한다.
- 스크린샷에서 읽히지 않는 제목·조회수는 추정하지 말고 `[판독 불가]`로 둔다.
- 결과는 대화창에도 보여주고, `video/benchmark/`에 파일로 저장한다. 대화가 길어지거나 끊겨도 이어 쓸 수 있어야 한다.

이 스킬의 스크립트 경로를 `$S`라고 부른다 (`.claude/skills/channel-benchmark-script/scripts`).

## 전체 흐름 (사용자 입력 4번)

| 단계 | 사용자가 주는 것 | 결과 (저장 파일) |
|---|---|---|
| 1 | 채널 영상 목록 스크린샷 (인기순) | 채널 분석 + 아이디어 10개 (`01_channel.md`) |
| 2 | 주제 선택 | 자막 원고 요청 |
| 3 | 잘 된 영상 2~3개의 자막 원고 전문 | 문체 분석 + 제목 5개·추천 1개 + 대본 (`03_script.md`, 원고는 `sources/`) |
| 4 | 영상 본편 장면 이미지 3~5장 | 화면 분석 + 전 구간 이미지 프롬프트 + 앞 10개 영상 프롬프트 (`04_image_prompts.md`, `04_video_prompts.md`) |

## 1단계 — 채널 스크린샷

시작하면 이렇게 요청한다:
> 벤치마킹할 유튜브 채널의 영상 목록 스크린샷을 올려 주세요. 채널 → 동영상 탭 → '인기순' 정렬 화면을 캡처하면 됩니다.

받으면 다음을 정리한다.
- 보이는 영상의 제목, 조회수, 업로드 시기를 표로 정리한다.
- 전문 분야, 대상 시청자, 콘텐츠 패턴을 정리한다.
- 제목 패턴을 분석한다: 반복되는 구조, 클릭을 끄는 심리 장치.
- 영상 아이디어 10개를 제안한다.
  - 사용자가 자기 경험을 다루는 채널이라면(예: AI 생존기), 아이디어는 사용자가 **실제로 겪은 일**에서 고른다. 근거가 없으면 `[경험 확인 필요]`로 표시한다.

끝에 "마음에 드는 주제를 골라 주세요. 다른 주제가 있으면 말씀해 주셔도 됩니다."라고 말하고 **멈춘다.**

## 2단계 — 주제 선택

> 이 주제로 대본을 쓰겠습니다. 이 채널에서 잘 된 영상 2~3개의 자막 원고 **전문**을 붙여 넣어 주세요. 요약은 안 됩니다. 영상 설명란 → 더보기 → '스크립트 표시' → 전체 복사.

**멈춘다.**

## 3단계 — 원고 → 분석 + 제목 + 대본

받은 원고를 `video/benchmark/sources/src1.txt`, `src2.txt`, …로 저장한 뒤 아래를 한 번에 진행한다.

1. **채널 분석**
   - 인트로 방식 (첫 30초 구조)
   - 원고 구조 (기승전결)
   - 문장 문체 (종결 어미, 문장 길이, 호칭)
   - 감정 곡선
   - 시청 유지 장치 (의문문, 떡밥, 수치 인용)
2. **문체 특성**
   - 단문·장문 리듬, 반복 장치, 어조 전환 지점
   - 호기심 유발, 감정 유발 요소
   - 직접 호칭 방식, 묘사 디테일 수준
3. **제목**: 1단계 제목 패턴과 채널 분석을 바탕으로 후보 5개를 만들고, 추천 1개를 이유와 함께 고른다. 내용이 뒷받침하지 않는 낚시성 과장은 뺀다.
4. **대본**
   - `python $S/text_check.py stats video/benchmark/sources/*.txt`로 평균 글자 수와 목표(+10%)를 **계산해서** 먼저 표시한다.
   - 첫 30초는 오프닝 훅을 강하게 쓴다. 문체, 리듬, 감정 곡선, 호칭 방식을 반영한다.
   - 마지막은 다음 영상 떡밥과 구독 유도로 끝낸다.
   - 사실 주장(수치, 사례)은 사용자가 준 자료에 있는 것만 쓴다. 없으면 `[확인 필요]`로 표시한다.
   - 다 쓰면 `03_script.md`로 저장하고 두 가지를 실행해 결과를 보여준다:
     - `stats`로 최종 글자 수
     - `python $S/text_check.py overlap video/benchmark/03_script.md video/benchmark/sources/*.txt`로 표절 점검. 겹침이 있으면 해당 문장을 고쳐 0개로 만든다.

끝에 "영상 화면으로 쓸 장면 이미지 3~5장을 올려 주세요. 썸네일이 아니라 본편 장면입니다."라고 말하고 **멈춘다.**

## 4단계 — 장면 이미지 → 프롬프트

1. **화면 분석**: 화풍, 색상 팔레트, 조명, 카메라 앵글, 구도, 디테일 수준, 분위기를 정리하고 → **화면 문체 키워드** 한 줄로 요약한다.
2. **이미지 프롬프트** (`04_image_prompts.md`)
   - 대본 **전 구간**을 3~5초(한국어 낭독 약 20~35자) 단위로 나눈다. 빠지는 구간이 없어야 한다.
   - 형식: `[대본 텍스트] image description / camera angle / lighting / mood / action`
   - 라벨만 한국어로 쓰고 본문은 영어로 쓴다. 모든 프롬프트에 화면 문체 키워드를 넣는다.
   - 프롬프트마다 독립적으로 완결되게 쓴다. "same as before" 같은 앞 장면 참조는 쓰지 않는다.
   - 실존 인물 얼굴, 브랜드 로고, 특정 작가 이름의 화풍 지정은 넣지 않는다. 생성 도구에서 거부되거나 권리 문제가 생긴다.
3. **영상 프롬프트** (`04_video_prompts.md`): 앞 10개 장면만 쓴다.
   - 각 3~5초, 영어 본문 + 한국어 라벨
   - 피사체 움직임과 카메라 움직임(줌인, 패닝, 정적)을 구체적으로 적는다.
4. 결과를 보여주고 끝낸다. 사용 안내 한 줄을 덧붙인다: "이미지 프롬프트는 구글 플로우(https://labs.google/fx/ko/tools/flow)에 붙여 넣으면 됩니다."

## ai-survival-video와 함께 쓰기

이 스킬의 대본을 슬라이드형 강의 영상으로 렌더링하려면, `03_script.md`의 문장을 40자 이내로 나눠 ai-survival-video의 `script.json` narration에 넣고 그 스킬의 STEP 4~5를 따른다.

| 원본 | 바뀐 점 | 이유 |

| 결과는 대화창에만 | `video/benchmark/`에 단계별 파일 저장 | 대화가 끊겨도 이어 쓸 수 있게 |
| 사실 확인 규칙 없음 | 자료에 없는 수치·사례는 `[확인 필요]` | 채널 신뢰도 |
